evidence was recorded without launching any Run3 or game executable. The
existing game log predates this inventory and is treated as an observation,
not as proof of a complete or clean play-through.

The tree-manifest digest is calculated deterministically from every relative
path, byte size, and per-file SHA-256. Re-run the inventory whenever the
tracked worktree or local evaluation content changes:

```powershell
python tools/inventory.py
python tools/inventory.py --file-hashes
```

```bash
python3 tools/inventory.py
python3 tools/inventory.py --file-hashes
```

The script writes only to standard output. Redirecting that output to a file is
an explicit caller action. A checkout without the game content can use
`--no-content`; a different authorized tree can be selected with
`--content-root PATH`.

## Legacy build baseline

- `Run3.vcproj` is Visual Studio project format 7.10 with `Debug|Win32` and
  `Release|Win32` configurations.
- It declares 270 unique files, including 268 C/C++ source/header files; all
  are present in this worktree. The modern
  root CMake project intentionally does not compile them yet.
- Debug output is hard-coded below `F:\VARIOUS_BACKUPS!\Run3v0.72`; Release
  output is hard-coded below `C:\Run3v0.72`.
- Link and post-build settings depend on `$(OGRE_HOME)`, relative dependency
  folders, and numerous absolute `C:`/`D:`/`F:` paths. The full grouped
  inventory is in [DEPENDENCIES.md](DEPENDENCIES.md) and can be regenerated by
  `tools/inventory.py`.
- The AIR3 submodule is pinned to
  `6fd06acf662ababd4d5092bd14699fa61b370dad` (2016-05-13).

## Attaching VM recordings and logs

1. Give each capture a stable ID such as `legacy-YYYYMMDD-machine-scenario`.
2. Record the VM OS, virtual/physical GPU mode, display settings, input steps,
   executable SHA-256, content manifest SHA-256, start/end time, and outcome in
   a small text metadata file.
3. Copy the new Run3 and CEGUI logs only after shutting the VM down. Do not
   overwrite the preserved local log used above.
4. Compute hashes inside the VM with `Get-FileHash -Algorithm SHA256` or
   `sha256sum`. Hash recordings, logs, executable, configuration, and metadata.
5. Put large recordings and raw logs in approved external/private storage.
   Put working copies under `docs/porting/evidence-local/<capture-id>/` only if
   convenient; that directory is ignored by Git.
6. Add the stable URI and hashes to the matrix above. A small sanitized text
   log may be committed under `docs/porting/evidence/` when it contains no
   machine secrets or bundled assets. Do not commit a game binary or asset dump.
7. Note every divergence rather than editing the evidence. A later port test
   should link back to the capture ID it is intended to reproduce.
